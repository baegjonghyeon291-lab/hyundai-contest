# 2차 PT 뼈대 (12/3~4 · 오프라인 · 현대자동차 강남대로사옥)

1차 통과(11/23 발표) 후 쓰는 초안. 발표 시간·분량은 통과 안내 메일을 받은 뒤 맞춘다. **실제 동작 앱 시연 필수.**

## 한 줄 메시지
골목에서 사람이 튀어나오기 *전에* 차를 멈출 수 있는 상태로 만들고, 사고가 나도 운전자가 **무엇을 했는지** 숫자로 남긴다.

## 라이브 시연 시나리오 (3분, 영상과 동일 순서)
1. 큰길 40km/h → 좌회전 깜빡이 + 핸들 → "곧 골목길입니다" 예고
2. 골목 진입 → 기준 20 안내, 무드등 호박색·창문 10%·볼륨 절반
3. 35km/h 과속 → "위험! 버스정류장 앞" + 무드등 적색 → 15km/h로 감속
4. 큰길 복귀 → 원래대로 복원
5. 재진입 → 16km/h 서행 중 충격 → 사고 카드 → **리포트: 기준 20 · 16 → 준수 ✓**
6. 맡김 모드(발레): 90km/h 운행 → 돌려받기 → 의심 운행 판정

**시연 리스크와 대비**
- 에뮬레이터는 PC 메모리가 부족하면 ANR·재부팅이 난다 → 발표 PC는 다른 프로그램을 닫고, **창 모드로 미리 15분 워밍업**. 실패 대비로 `docs/out/백종현_골목지킴이_시연영상.mp4`를 바로 재생할 수 있게 준비.
- 현장 네트워크가 막히면 `/api/road`가 실패 → 골목 판정이 안 된다. 시연 구간(연남동·강남)은 서버 캐시로 응답하지만, **현장 와이파이/테더링을 반드시 사전 확인**.
- 부팅 직후 Wi-Fi가 안 붙으면 `adb shell svc wifi disable` → `enable`.
- 데모 트리거는 디버그 APK(`DemoReceiver`)에만 있다. 현장에서는 **디버그 APK**로 시연, 제출용 release APK와 구분.

## 예상 질문 (미리 답 준비)
| 질문 | 답변 방향 |
|---|---|
| 보행자를 감지하는 건가? | 아니오. 레이더·카메라 접근이 없어 "튀어나오기 전" 예방(속도·시야·위치 정보)에 집중. ADAS API 개방 시 입력만 교체 |
| 주행 중 창문을 여는 게 위험하지 않나? | 운전석 10%, 설정에서 끌 수 있음. 목적은 운전자가 외부 소리를 듣게 하는 것 |
| 사고 리포트가 과속 증거로 쓰이면? | 운전자 소유 데이터, 공유는 본인이 QR로 보낼 때만. 준수·초과 모두 그대로 기록 |
| 골목 판정 정확도는? | 내비 주의지점 + OSM 도로 등급·제한속도 + 깜빡이·핸들·다음 회전의 조합. 실차 검증 항목으로 명시 |
| 전조등·안개등·에어백은 실제로 되나? | 에뮬레이터 한계(전조등 set 오류 50001, 안개등·에어백 미지원). 실차 검증 계획 |
| 시장 규모·MAU? | 탑재 대수 비공개 → 보수적 가정으로 산정, 부팅 자동 시작이라 설치=MAU |
| 핫스팟 데이터 프라이버시? | 위치·시각·직전 속도만, 식별 정보 없음, 50m 격자 집계 |
